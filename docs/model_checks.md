# Checkpoint checks

Every saved checkpoint is reloaded from disk and its held-out metric recomputed, so the number in the report is a property of the published weights rather than of the run that produced them. Generated by `scripts/verify_models.py`.

| qa | `full_ft_linear_bert-base-uncased` | F1 | 82.137 | 82.173 | 0.0360 | 16 | cuda → mps (cross-device) |

Tolerance 0.0001. Each checkpoint is re-scored with the evaluation batch size its own run used: padding is per batch, so a different grouping changes the shapes the matmuls see and, in reduced precision, can move a logit enough to flip a near-tied answer span. Reductions on GPU/MPS are not bit-exact either, so the last decimal is allowed to move.

Cross-device rows were trained on one device and re-scored on another, which also changes the reduced-precision format (float16 on a T4, bfloat16 on MPS); they are held to 0.1 points of the headline metric instead. On the device it was trained on, the same checkpoint was re-scored by the teammate's notebook and matched exactly (`docs/replica_t4.md`).
